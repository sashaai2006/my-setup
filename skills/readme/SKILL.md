# README

Создавай или обновляй `README.md` как воспроизводимую инструкцию к текущему репозиторию. Документируй наблюдаемое поведение, а не предполагаемый дизайн.

## Выбор операции

- При отсутствии целевого `README.md` выполняй **create-readme**.
- При наличии целевого `README.md` выполняй **update-readme**, включая запрос на переработку.
- По умолчанию работай с корневым `README.md`. Явно указанный пользователем путь имеет приоритет.
- В монорепозитории обновляй только запрошенную область. Не создавай README во вложенных пакетах без запроса.
- Изменяй только документацию. Исправляй код, конфигурацию и тесты только по отдельному запросу.

## Общий процесс

1. Определи тип проекта, целевую аудиторию и основной сценарий использования.
2. Изучи только релевантные источники:
   - существующие документацию и примеры;
   - манифесты, lock-файлы и конфигурацию инструментов;
   - точки входа, публичные интерфейсы и CLI;
   - скрипты установки, сборки, запуска и тестирования;
   - Docker, CI и конфигурацию развёртывания;
   - примеры переменных окружения;
   - `LICENSE`, `CONTRIBUTING` и связанные файлы.
3. Сопоставь ключевые утверждения с кодом и конфигурацией. Используй тесты как примеры ожидаемого поведения, но не считай их доказательством работоспособности без прогона.
4. При противоречии источников приоритизируй подтверждённое выполнением поведение, затем актуальные код и конфигурацию, затем тесты и документацию. Существенное неразрешённое противоречие укажи в итоговом отчёте.
5. Составь документ по [references/project-types.md](references/project-types.md). Загружай этот файл перед выбором структуры README.
6. Проверь результат и завершай работу только после выполнения критериев ниже.

## create-readme

1. Построй минимальный маршрут от чистого окружения до наблюдаемого результата: требования → установка → конфигурация → запуск или первый вызов → проверка результата.
2. Начни с названия и конкретного описания: что делает проект, для кого предназначен и какую задачу решает.
3. Добавляй только подтверждённые возможности и ограничения.
4. Используй реальные команды, версии, имена параметров и примеры интерфейсов.
5. Подключай необязательные разделы по типу проекта; не создавай пустые разделы ради шаблона.

## update-readme

1. Прочитай весь существующий файл и сохрани его язык, терминологию, разумную структуру и полезные проектные соглашения.
2. Выяви устаревшие команды, ссылки, интерфейсы и утверждения. Не считай существующий README достоверным только потому, что он уже есть.
3. Вноси минимальный достаточный diff. При точечном запросе не переписывай остальной документ.
4. Сохраняй актуальные пользовательские разделы, badges, ссылки, диаграммы и предупреждения. Удаляй их только при подтверждённой неактуальности или прямом запросе.
5. При полной переработке сначала зафиксируй полезное содержимое старого файла и перенеси всё актуальное в новую структуру.
6. Не меняй работающую документацию ради стилистических предпочтений.

## Правила содержимого

- Выбирай язык в порядке приоритета: явный запрос пользователя → существующий README → основная документация проекта → язык текущего запроса.
- Пиши конкретно, без маркетинговых клише, неподтверждённых превосходств и описания нереализованных возможностей.
- Делай быстрый старт самодостаточным: рабочий каталог, зависимости, команды, обязательная конфигурация и способ проверить успех.
- Указывай версии и платформы только если они заданы проектом или подтверждены проверкой.
- Приводи воспроизводимые примеры с необходимыми импортами, аргументами и контекстом выполнения.
- Документируй только публичные интерфейсы. Внутреннее устройство добавляй лишь при пользе для запуска, разработки или сопровождения.
- Для параметров конфигурации указывай назначение, обязательность и подтверждённое значение по умолчанию.
- Заменяй секреты условными значениями. Не копируй реальные токены, пароли, ключи и приватные URL.
- Добавляй badges только для существующих сервисов и корректных URL.
- Не выдумывай лицензию. При отсутствии лицензионного файла не объявляй проект открытым или свободно распространяемым.
- Оформляй валидный Markdown: один основной заголовок, последовательная иерархия, языковые идентификаторы у блоков кода, корректные таблицы и ссылки.
- Не оставляй `TODO`, `TBD`, `placeholder`, `coming soon` и другие заглушки. Если необязательные сведения неизвестны, исключи соответствующий фрагмент.

## Нехватка данных

Не останавливай работу из-за отсутствия необязательных сведений и не заполняй пробелы догадками. Если запуск или использование невозможно документировать без критических данных, сохрани подтверждённую часть и перечисли блокирующие вопросы в итоговом отчёте. Не маскируй неизвестное универсальными формулировками.

## Верификация

1. Выполни доступные безопасные проверки документируемого маршрута. Не публикуй пакеты, не развёртывай проект, не обращайся к production-ресурсам и не выполняй деструктивные операции.
2. Если команда небезопасна, требует внешних данных или слишком дорога, проверь её статически и явно укажи ограничение.
3. Запусти из каталога навыка:

   ```bash
   python3 scripts/check_readme.py <путь-к-README.md>
   ```

4. Исправь ошибки проверки. Предупреждения разбери по существу, а не игнорируй автоматически.
5. Проверь локальные ссылки, команды, имена переменных, примеры и отсутствие секретов.
6. Просмотри итоговый diff: все изменения должны относиться к задаче, а актуальное пользовательское содержимое — сохраняться при update-readme.

Скрипт проверяет механические дефекты, но не доказывает истинность документации или работоспособность проекта.

## Критерии завершения

Завершай, когда:

- целевой `README.md` сохранён;
- основной сценарий ведёт к наблюдаемому результату либо блокирующие пробелы явно названы;
- утверждения подтверждены репозиторием или выполненными проверками;
- механические проверки пройдены;
- непроверенные команды и неразрешённые противоречия перечислены отдельно.

В итоговом ответе кратко укажи путь к файлу, создан он или обновлён, что проверено выполнением, что проверено только статически и какие сведения остались неизвестными. Не вставляй весь README в чат, если файл уже сохранён.
